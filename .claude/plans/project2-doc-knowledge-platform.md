## Problem statement

A 400-person company keeps knowledge in three forms: **policy PDFs**, **scanned expense and leave forms**, and **text-based files** (CSV pricing tables and plain-text or Markdown FAQs). Employees cannot find anything. The last chatbot attempt gave confident answers with no sources.

Requirements:

1. Every answer cites the document and the page, section, or row it came from.
2. People only retrieve documents their department may see. The filter runs **inside** the search, not after it.
3. When a policy is replaced, answers reflect the new version within minutes and the old version stops appearing.
4. Bad files (wrong type, empty, corrupt, unreadable scan) are quarantined with a reason and never reach the index.
5. Other tools, including an agent built later, can call retrieval through a standard interface (function calling and MCP).

**Goal:** Build the whole path from file upload to cited answer, build the vector store twice (S3 Vectors, then Aurora pgvector), and compare your pipeline against a managed Bedrock Knowledge Base using the same questions.

## Architecture

### Ingestion path (event-driven)

```
S3 raw bucket  (prefix per department: hr/, finance/, sales/, legal/, company-wide/)
    │  "Object Created" / "Object Deleted"
    ▼
EventBridge rule ──► SQS queue ──(after 3 failed receives)──► Dead-letter queue
    │
    ▼
Lambda "starter"  ──► Step Functions (Standard) ingest workflow
    │
    ├─ Route on event type
    │    ├─ Object Deleted ──► delete_document Lambda ──► remove vectors + manifest row
    │    └─ Object Created ▼
    ├─ Validate (type by magic bytes, size, zero-byte, SHA-256 hash, unchanged-hash skip)
    │    └─ invalid ──► Quarantine (copy + reason JSON + CloudWatch metric)
    ├─ Branch by kind
    │    ├─ scanned PDF ──► Textract (text, tables, layout) ──► poll until done
    │    ├─ text PDF    ──► pypdf (no Textract needed)
    │    └─ CSV / txt / md ──► row-to-text or section rendering
    ├─ Validate content (empty after extraction? language?)  ── invalid ──► Quarantine
    ├─ Clean + enrich (normalize, PII, entities)
    ├─ Chunk (structure-aware, per modality)
    ├─ Embed in batches (Titan Text Embeddings V2, 1024 dims)
    ├─ Upsert vectors + metadata   (S3 Vectors in M2–M6, pgvector from M7)
    └─ Write DynamoDB manifest, then delete the previous version's chunks
```

Step Functions carries **S3 pointers, not document text**. A state machine payload is limited to 256 KB, and a 50-page PDF exceeds that.

### Query path (FastAPI on ECS Fargate)

```
Employee question + caller identity
    │
    ▼
FastAPI retrieval service ── resolve caller → allowed departments (never trust a client-sent department)
    ├─ Query rewrite / expansion        (small Bedrock model, Converse)
    ├─ Embed query                       (Titan V2)
    ├─ Vector search + department filter ┐
    ├─ Keyword search (pgvector tsvector)┴─► merge (reciprocal rank fusion)
    ├─ Rerank top-k=30 → top-n=5         (Bedrock Rerank API)
    └─ Converse: answer using <source id=…> blocks, with citations
         │
         └─ response: { answer, citations:[{doc, page|locator, s3_uri}] }

FastMCP server ──► search_documents(query, department)  (same retrieval code)
Converse toolConfig ──► the same tool exposed to a model for function calling
```

### Build-vs-buy path (M9)

```
Same documents ──► Bedrock Knowledge Base (S3 data source → S3 Vectors store)
                    └─ same golden questions → recall@5, latency, cost, effort → decision note
```

## Metadata schema (designed in M1, used everywhere)

S3 Vectors limits filterable metadata size and key count, so only fields you filter on are filterable. Long text goes in a **non-filterable** key. Confirm the current limits on the S3 Vectors limits page before M2.

| Field | Filterable | Used for |
|---|---|---|
| `department` | yes | Access filter. One of `hr`, `finance`, `sales`, `legal`, `company-wide` |
| `doc_id` | yes | Delete by document, citations. SHA-256 of the S3 key, truncated |
| `version` | yes | Freshness: only the current version is searchable |
| `modality` | yes | `pdf`, `scan`, `csv`, `text` |
| `effective_date` | yes | Freshness rules and date filters |
| `page` | no | Citation for PDFs and scans |
| `locator` | no | Citation for non-paged content: `rows 12–18` (CSV), `§ Parental leave` (txt/md) |
| `s3_uri` | no | Link back to the source |
| `chunk_text` | no | The text sent to the model |

Chunk id format: `{doc_id}#v{version}#{n}`. It is deterministic, so a delete never needs a search.

### Milestone 2 — Text-only pipeline on S3 Vectors
**Exam skills:** 1.5.1, 1.5.2, 1.5.3, 1.4.1, 1.4.2, 1.3.3  
**AWS cost:** S3 Vectors storage and queries are pennies. Titan embedding tokens are cents for this corpus.

#### Why this matters — a concrete scenario

The last chatbot answered confidently with no sources. The cause was not the model. It was retrieval: pages were split mid-sentence, nothing recorded which page a chunk came from, and nobody could tell whether the right passage was even retrieved. This milestone builds the smallest end-to-end loop (file → vectors → cited answer) and measures it, so the baseline exists before any orchestration is added.

#### How it works

```
ingest_local.py
  S3 object ──pypdf──► text per page ──chunk (≈300 tokens, 15% overlap, never cross a page)──►
  Titan V2 embed (1 call per chunk, run 8 at a time) ──► s3vectors.put_vectors(key, vector, metadata)

POST /ask  { question }  + header X-User-Id
  1. caller → allowed departments           (access.py)
  2. embed question
  3. s3vectors.query_vectors(topK=5, filter={"department": {"$in": [...]}})
  4. build prompt:
       <source id="1" doc="hr/leave-policy.pdf" page="3"> …chunk text… </source>
       "Answer only from the sources. Cite as [1], [2]. If the sources do not answer, say so."
  5. converse() ──► answer text
  6. answer.py checks every [n] exists in the sources; maps n → {doc, page, s3_uri}; drops unknown ids
  7. response: { answer, citations: [...] }
```

**Chunking choice.** Fixed-size chunks that respect page boundaries are the baseline. Page boundaries keep citations exact. M5 adds structure-aware chunking for tables, text sections and CSV rows. Titan V2's API takes one text per call, so "batching" means concurrent calls with a limit, not one multi-text request.

**Why a filter inside the query.** If you search first and filter after, a user from Finance can crowd the top 5 with HR chunks, get filtered down to nothing, and see "no results" even though relevant Finance chunks existed.

### Milestone 3 — Validation and quarantine
**Exam skill:** 1.3.1  
**AWS cost:** negligible

#### Why this matters — a concrete scenario

Someone uploads a 0-byte "leave-policy.pdf" and a renamed `.exe`. Without validation, the first crashes the extractor halfway through a batch, and the second either fails the same way or silently indexes garbage. A blank scan is worse. It passes every structural check, produces zero text, and creates a document that exists in the manifest but can never be found. Quarantine turns each of these into a visible, explained rejection instead of a mystery.

#### How it works

Two validation stages, because some failures only show up after extraction:

```
Stage 1 (before extraction)             Stage 2 (after extraction)
  size == 0            → EMPTY_FILE       text length < N chars      → NO_TEXT
  size > limit         → TOO_LARGE        language not allowed       → UNSUPPORTED_LANGUAGE
  magic bytes ≠ ext    → TYPE_MISMATCH    (scan with no text)
  pypdf cannot open    → CORRUPT
  same SHA-256 as manifest → SKIP (not an error, a no-op)

invalid ─► quarantine:
   copy object → s3://dkp-quarantine-<acct>/<dept>/<key>
   write      → <key>.reason.json  { reason, detail, stage, sha256, timestamp }
   metric     → DocKnowledge / FilesRejected  (dimension Reason) + an aggregate with no dimension
   manifest   → status = QUARANTINED
```

**Why the metric is emitted twice.** CloudWatch treats `FilesRejected{Reason=CORRUPT}` and `FilesRejected` (no dimensions) as different metrics. An alarm on the dimensionless name sees nothing if you only emit the dimensioned one. Emit both, or alarm on a metric-math `SUM(SEARCH(...))`. Background: `docs/concepts/metrics_and_alarms.md`.

**Why a separate quarantine bucket.** Writing into the raw bucket would fire another "Object Created" event and loop.

### Milestone 4 — Event-driven ingestion
**Exam skills:** 1.4.4, 1.3.1 (retries and failure routing)  
**AWS cost:** SQS, EventBridge, Step Functions Standard (state transitions) — pennies at this volume

#### Why this matters — a concrete scenario

On the first Monday of the quarter, HR drops 200 policy files into the bucket in two minutes. A script that processes each file inline either times out or overwhelms Textract. With a queue in front, uploads finish immediately, a limited number of workflows run at once, and a document that fails three times lands in a dead-letter queue where you can see it instead of vanishing.

#### How it works

```
upload ──► S3 ──► EventBridge ──► SQS ──► Lambda starter ──► Step Functions execution
                                   │
                                   └─ 3 failed receives ─► DLQ  (alarm on DLQ depth > 0)
```

1. S3 sends "Object Created" to EventBridge (the bucket's EventBridge notification setting must be **on**, it is off by default).
2. An EventBridge rule matches the raw bucket and puts the event on SQS. The queue policy must allow `events.amazonaws.com` to `sqs:SendMessage`.
3. The starter Lambda reads a message and calls `StartExecution`. The execution **name** is a hash of bucket + key + ETag. S3 and SQS deliver at least once, and a repeated name with the same input is rejected, which gives you idempotency for free.
4. The state machine follows the diagram in the Architecture section. Every task has `Retry` (exponential backoff, only for transient errors) and `Catch` that routes to the quarantine step with the error attached.
5. For M4 the branches after validation are stubs. Only text PDFs flow through chunk → embed → upsert.

Concurrency control: SQS → Lambda `maximum concurrency` = 2 and `batch size` = 1 limit how many documents are processed at once.

### Milestone 5 — Scans, CSV, text files, and enrichment
**Exam skills:** 1.3.2, 1.3.3, 1.3.4, 1.5.1 (structure-aware chunking)  
**AWS cost:** Textract per page (tables and layout cost more than plain text detection). Keep scans few. Check current pricing before the first run.

#### Why this matters — a concrete scenario

An employee asks "What is the per-diem for Singapore?" The answer is in row 14 of a pricing CSV. If you embed the raw CSV as one blob, the row is lost in noise. Another asks about the expense limit, and the only source is a scanned form with no text layer, which pypdf reads as empty. Each content type needs its own extraction **and** its own chunk shape so that retrieval and citations are precise.

#### How it works

| Content | Extraction | Chunk shape | Citation |
|---|---|---|---|
| Text PDF | pypdf (M2) | Page-bounded, ~300 tokens | `page` |
| Scanned PDF / image | Textract `StartDocumentAnalysis` with LAYOUT + TABLES (async: start → wait → get) | One chunk per layout section. A table becomes one chunk, rendered as markdown or sentences | `page` |
| CSV | Python `csv` | Each row (or logical group) rendered as a sentence: `"Item: Premium support. Region: APAC. Price: 1,200 USD per year."` | `locator` = `rows 12–14` |
| `.txt` / `.md` | UTF-8 read | Split by Markdown heading, then by paragraph to ~300 tokens. Heading path kept in the chunk | `locator` = `§ Heading` |

The state machine routes text PDFs and scans differently. A cheap pre-check (does pypdf return meaningful text per page?) sends image-only PDFs to Textract and skips Textract's cost for text PDFs.

```
Step Functions async pattern (Textract):
  Start job ─► Wait 10s ─► Get job status ─► Choice
                              ├─ IN_PROGRESS ─► back to Wait (max attempts, then Catch → quarantine)
                              ├─ SUCCEEDED   ─► Parse → write extracted.json to work bucket
                              └─ FAILED      ─► quarantine
```

**Enrichment (1.3.4)** runs once on the extracted text before chunking:
- Normalize: Unicode, collapse whitespace, remove repeating headers/footers, fix hyphenated line breaks.
- PII: regex for obvious patterns (card numbers, national ID formats, emails, phone). Redact card and ID patterns in indexed text. Tag the document with `pii_types` in the manifest. If Comprehend is available, call `DetectPiiEntities` as a second pass. Otherwise use a Bedrock prompt for entities.
- Entities (optional): extract named policies, products, regions into the manifest for later filters.

**Formatting for inference (1.3.3):** the `<source …>` wrapper from M2 gains a `locator` attribute so the model can cite rows and sections.

### Milestone 6 — Freshness
**Exam skill:** 1.4.5  
**AWS cost:** negligible (DynamoDB, EventBridge Scheduler or a scheduled rule)

#### Why this matters — a concrete scenario

HR replaces the leave policy: parental leave goes from 12 to 16 weeks. The new file has the same key as the old one. If you only add chunks, the index now contains both versions, and the model may quote 12 weeks with a citation to a document that "says" 16. Worse, if a file is deleted and nothing removes its vectors, a withdrawn policy keeps answering questions forever.

#### How it works

```
Manifest row (DynamoDB)
  doc_id | s3_key | department | content_hash | version | status | chunk_ids[] | updated_at

Update (same key, new content):
  1. Validate computes SHA-256 → differs from manifest → proceed (same hash → SKIP, nothing to do)
  2. new_version = old_version + 1
  3. Write new chunks with ids  {doc_id}#v{new_version}#{n}     ← both versions exist briefly
  4. Update manifest: version = new, chunk_ids = new, hash = new   ← the switch
  5. Delete old chunk ids                                          ← cleanup
  Search filter includes version == manifest.version (or a post-check) so a crash between 3 and 5
  never shows old and new together.

Delete event:
  delete_document Lambda → read chunk_ids from manifest → delete vectors → status = DELETED

Nightly reconciliation (scripts/reconcile.py or a scheduled Lambda):
  list bucket keys  vs  manifest rows
    in bucket, not in manifest   → enqueue ingest
    in manifest, not in bucket   → delete vectors, mark DELETED
    chunk count mismatch         → re-ingest
```

**Order matters.** Write new first, delete old second. Reversing it leaves a gap where the document has no chunks at all.

| `scripts/reconcile.py` | New |

### Milestone 7 — Retrieval upgrades
**Exam skills:** 1.5.3, 1.5.4, 1.5.5, 1.4.1 (second store)  
**AWS cost:** Aurora Serverless v2 bills while running. Rerank bills per search unit. Stop or delete the cluster when not testing.

> **Rule for this milestone:** change one thing, re-run the golden set, record recall@5 and p95 latency, then change the next thing.

#### Why this matters — a concrete scenario

A user searches "error ERR-4021". Pure vector search returns documents about errors in general, because the identifier carries almost no semantic signal. Another user asks "can I expense my gym?" and the policy says "wellness reimbursement". Keyword search misses it, vector search finds it. You need both, and then a second pass that reads each candidate together with the question to put the right one first. Each upgrade costs latency and money, so each must show a measured gain.

#### How it works

```
Baseline            embed(q) → vector search (S3 Vectors) → top 5
+ Rewrite           small model rewrites "can i claim gym" → "wellness reimbursement policy gym membership"
                    (also: expand abbreviations, resolve "that policy" from chat history, optional multi-query)
+ Hybrid            move store to Aurora pgvector:
                      vector top 30  ─┐
                      tsvector top 30 ─┴─ reciprocal rank fusion: score = Σ 1 / (60 + rank)
+ Rerank            Bedrock Rerank on the top 30 → keep 5
                    (agent-runtime rerank, model amazon.rerank-v1:0 or cohere.rerank-v3-5:0, in RERANK_REGION)
```

**Why a second store.** S3 Vectors has no keyword search. Aurora pgvector keeps vectors, metadata, a full-text index and a department `WHERE` clause in one SQL query. The `VectorStore` protocol from M2 keeps both implementations behind the same `search()` call, so the golden set runs unchanged.

Hybrid query shape (one round trip through the Data API):

```sql
WITH v AS (
  SELECT chunk_id, ROW_NUMBER() OVER (ORDER BY embedding <=> CAST(:emb AS vector)) AS r
  FROM chunks WHERE department = ANY(:depts) AND version_current ORDER BY embedding <=> CAST(:emb AS vector) LIMIT 30),
k AS (
  SELECT chunk_id, ROW_NUMBER() OVER (ORDER BY ts_rank_cd(tsv, plainto_tsquery('english', :q)) DESC) AS r
  FROM chunks WHERE department = ANY(:depts) AND tsv @@ plainto_tsquery('english', :q) LIMIT 30)
SELECT c.*, COALESCE(1.0/(60+v.r),0) + COALESCE(1.0/(60+k.r),0) AS score
FROM chunks c LEFT JOIN v USING (chunk_id) LEFT JOIN k USING (chunk_id)
WHERE v.chunk_id IS NOT NULL OR k.chunk_id IS NOT NULL
ORDER BY score DESC LIMIT 30;
```

The Data API takes array parameters as text, so you may need `string_to_array(:depts, ',')`. Adjust when you run it. Table definition:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE TABLE chunks (
  chunk_id text PRIMARY KEY, doc_id text NOT NULL, department text NOT NULL, version int NOT NULL,
  modality text, page int, locator text, effective_date date, s3_uri text,
  chunk_text text NOT NULL, embedding vector(1024) NOT NULL,
  tsv tsvector GENERATED ALWAYS AS (to_tsvector('english', chunk_text)) STORED);
CREATE INDEX ON chunks USING hnsw (embedding vector_cosine_ops);
CREATE INDEX ON chunks USING gin (tsv);
CREATE INDEX ON chunks (department);
```

| Baseline | S3 Vectors | | | |
| + rewrite | S3 Vectors | | | |
| + hybrid | Aurora pgvector | | | |
| + rerank | Aurora pgvector | | | |

### Milestone 8 — MCP and function-calling access
**Exam skill:** 1.5.6  
**AWS cost:** token charges only

#### Why this matters — a concrete scenario

The HR team builds an onboarding agent next quarter. If it has to copy your retrieval code or call a private endpoint with a custom contract, you now maintain two retrieval stacks and the access rules drift apart. A standard tool interface lets any agent or model call `search_documents` and get cited, permission-filtered chunks, with the filtering enforced on your side.

#### How it works

```
              ┌── HTTP:  POST /search  (FastAPI)
retrieval.py ◄┼── MCP:   FastMCP tool  search_documents(query, department)
              └── Bedrock Converse toolConfig  → model emits toolUse → your code runs retrieval → toolResult
```

Function-calling loop:

```
1. converse(messages, toolConfig={tools:[{toolSpec:{name:"search_documents", inputSchema:{json:{...}}}}]})
2. stopReason == "tool_use" → read toolUse {toolUseId, input:{query, department}}
3. run retrieval (with the caller's allowed departments enforced here) → chunks with citation fields
4. append toolResult {toolUseId, content:[{json:{results:[...]}}]} → converse again
5. final answer cites the returned sources
```

**Security point to settle in the design.** The study guide's signature is `search_documents(query, department)`. If the model chooses `department`, a prompt injection could ask for another department. So the tool validates `department` against the caller's allowed set (resolved from identity, not from model output) and returns an error for anything else. For the learning build, identity is the `X-User-Id` header mapped through `access.py`. A real deployment would use a verified token claim (Cognito or IAM Identity Center). That is listed under stretch ideas.

| `access.py` | `resolve_departments(caller)`, `assert_allowed(caller, department)` |
| `scripts/tool_loop_demo.py` | New. Converse tool-use loop |
| AWS | None |

  ```bash
    --vector-ingestion-configuration '{"chunkingConfiguration":{"chunkingStrategy":"FIXED_SIZE","fixedSizeChunkingConfiguration":{"maxTokens":300,"overlapPercentage":15}}}'
  aws bedrock-agent start-ingestion-job --knowledge-base-id <kb-id> --data-source-id <ds-id>
  aws bedrock-agent-runtime retrieve --knowledge-base-id <kb-id> \
    --retrieval-query text="parental leave" \
    --retrieval-configuration '{"vectorSearchConfiguration":{"numberOfResults":5,"filter":{"equals":{"key":"department","value":"hr"}}}}'
  ```

## Cost and account notes

- Idle cost is the main risk. OpenSearch Serverless collections and always-on Aurora bill while you sleep. Aurora uses scale-to-zero if your engine version supports it, otherwise delete or stop it between sessions.
- Textract bills per page. Keep scans few (about 6–8 documents of 1–3 pages).
- S3 Vectors has limits on metadata size and key count. Check the current limits before M2.
- Textract may be unavailable on some account plans. If it is, drop scans and keep text PDFs, CSV and txt/md. The M1 preflight tells you before you design around them.
- Rerank is unavailable in `ap-southeast-2`. See decision 1.
- Delete the Knowledge Base, the Aurora cluster, the ECS service and the ALB when you stop for the day. `scripts/cleanup.sh` does all of it.
- Never commit `.env`, secrets, or private resource ids. Use `.env.example`.
